1. The Deadlock (Phase 2):
- เกิดขึ้นจากภาวะ Circular Wait เมื่อ Model A ครอบครอง GPU 0 แล้วรอคอย GPU 1 ในขณะที่ Model B ครอบครอง GPU 1 แล้วรอคอย GPU 0 ทำให้ระบบหยุด ทั้งระบบ

2. Deadlock Avoidance (Phase 3):
- แก้ไขปัญหาด้วยการ Lock Ordering โดยกำหนดกฎให้ทุก Model ต้องร้องขอ GPU 0 ก่อน GPU 1 เสมอ เพื่อทำลายเงื่อนไข Circular Wait ทำให้ระบบทำงานต่อได้

3. Starvation & Banker's Algorithm (Phase 4):
- Starvation เกิดขึ้นเมื่อโปรแกรม Greedy Model แย่งทรัพยากรไปตลอดเวลา ทำให้โปรแกรม Polite Model ไม่ได้รัน ซึ่ง OS สามารถแก้ได้ด้วยเทคนิค Aging
- Banker's Algorithm ช่วยคำนวณและตรวจสอบสถานะของระบบล่วงหน้า (Safe State) ก่อนให้ทรัพยากร เพื่อป้องกันไม่ให้เกิด Deadlock
