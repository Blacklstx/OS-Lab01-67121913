3. Analysis (The GIL):
 Multithreading ไม่ทำให้โค้ดทำงานเร็วขึ้น เป็นเพราะภาษา Python มีข้อจำกัดที่เรียกว่า GIL (Global Interpreter Lock) ซึ่งจะล็อกไม่ให้ Thread หลายตัวของ Python ประมวลผลคำสั่งพร้อมกันบนหลายคอร์ CPU 

 Multiprocessing จึงเป็นทางเลือกที่ดีกว่าสำหรับงานที่ใช้ CPU หนักๆ (CPU-bound tasks) เช่น การทำ Data Augmentation ใน Machine Learning เพราะแต่ละ Process จะถูกแยกหน่วยความจำและแยก GIL ออกจากกันอย่างเด็ดขาด ทำให้ OS สามารถเเบ่งภาระงานไปรันคู่ขนานกันบน CPU ทุกคอร์

* Note on Zombie Processes: จากการทดลองระบบ OS Internals พบว่าหาก Parent Process สร้าง Child Process ขึ้นมาทำงาน แต่ลืมเรียกคำสั่ง os.wait() เพื่อรอรับสถานะการจบการทำงาน Child ที่ทำงานเสร็จแล้วจะกลายสภาพเป็น Zombie Process (สถานะ Z) ค้างอยู่ในระบบ
